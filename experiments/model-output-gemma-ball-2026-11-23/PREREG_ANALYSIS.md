# Preregistered analysis: integer ball on Gemma

Status: before scored data. No real Gemma ball sweep results were available or read in preparing this plan. [PREREG.md](PREREG.md) is the experimental protocol; this file fixes the analysis and its interpretations before implementing it. The preregistration and this analysis plan must be strict git ancestors of committed score records. Synthetic controls are not experiment results.

## Inputs and scope

Read the runner's append-only `results.jsonl` (one or more files, in any order); `results.out` is only its rounded human-readable projection and cannot settle threshold boundaries. The runner contract inspected is `ca10cdacd9b1251b989d5fb66578bfe7e8f2554e`. Keys are `model_id`, `text` (`wikitext`, `python`, `bridge`), and `variant`. The runner supplies a Boolean `bridge`, `model_sha256` (reference supplied to `--model-path`), `text_sha256`, optional `imatrix_sha256`, `kl_mean`, `kl_mean_se`, and `same_top` in **percentage points**, plus counted-all/active weight and bit summaries, and runtime/other metrics. See the analysis README for the full schema and handoff gaps.

Report the primary `gemma-4-E4B-it` first, and other preregistered model IDs separately (no model pooling). P7 is primary-model only. Headline scores use only the runner's non-bridge rows, declared to be from the 16-bit references and preregistered texts. Within each model require one headline reference hash, one text hash per text, and one real calibration hash across its matrix arms; never combine distinct references, text hashes or conflicting matrix hashes. The runner does not verify reference precision or the artifacts behind its hashes, prove cached reference freshness, or record the scored positions. Report those provenance limitations; no empirical verification of identity is implied by equal hash labels. P7 additionally requires operator evidence pinning the exact bridge model and text hashes and actual position count, because its prediction specifically compares the same historical setup.

Read JSON numeric lexemes into exact rationals, never through a Python float. KL is nonnegative, its SE is nonnegative, and top-1 is between 0 and 100 inclusive. Reject malformed input (including duplicate fields, duplicate cell keys, inconsistent provenance, malformed known fields, and partial KL/SE pairs), with no published verdict or audit entry. Runner `-Infinity` is allowed only in weight-error dB metadata where it denotes exactly zero error; it is not a score. A missing cell, absent top-1 metric, or metrics-only row is missing evidence, not zero. Unknown extra metadata is not scoring evidence. Predictions are `HOLD`, `FAIL`, `NOT_SCORED` (required evidence absent), or `NOT_APPLICABLE` (P7 on other models). For a conjunction a measured failure suffices to fail even if another condition is missing, except where a missing prerequisite makes that measured comparison inadmissible. Do not silently drop missing arms from rankings.

## Verdict rules

Throughout, a KL gain is comparator minus candidate. For a threshold of at least 2.0 SE, require a strictly positive gain and compare its square to `4 * (SE_candidate² + SE_comparator²)`, inclusively. This is the quadrature convention used by the earlier ball summaries, not a paired KL SE or a claim of statistical significance. All thresholds, deltas, ranking checks and SE comparisons are exact on the *serialized measured estimates*; their runner-side roundoff and sampling error remain. Equal KL is not a strict win.
