Plan for HANDOFF.md §5 Priority **1e**, committed **before any 27B data is produced**.
It extends `PREREG.md` (PR #47) and `PREREG-ADDENDUM-2026-11-24.md`; it changes no earlier claim.

## Question

Does the `4B -> 12B` block-rate advantage (ball arms vs tensor-matched `file:Q4_K_M-imat`,
iso-KL matched block savings) persist at 27B scale on a 64 GB host?

## Hard constraints (from HANDOFF §3.6 / §5 1e)

- **Never run BF16 27B on this 64 GB host** (~54 GB weights alone). The reference is
  `Q8_0` **only**; all 27B rows stay in a separate quantized-reference stratum and are
  never pooled with the 16-bit-reference rows or the `P7` bridge table.
- One model job at a time; no runner-commit switches while `multiprocessing` Pool
  workers are live.
- `other_tensors_that_differ == []` is required on **every** 27B row.

## Gates and verdict rules (mirroring 1b/1c, adapted to the Q8_0 stratum)

1. Pilot zero-codeword checks must all be exact (`0.0` error, `passed=true`) before the sweep.
2. Every row must have `other_tensors_that_differ == []`; any non-empty list halts
   interpretation of that row.
3. Stock baseline: `b_stock` = block bpw of `file:Q4_K_M-imat` **on this stratum**;
   `KL(stock)` = its mean WikiText KL. Recompute `hZBG128` matched-KL savings against this
   same-stratum stock (never against the BF16 12B figures).
4. Bracket rule per family (`hZBG128`, `hEBG128`) with `b496` + `b560`, requiring monotone
   `KL(b560) < KL(b496)` on each text (else halt, bracket anomalous):
   - below (`KL(b496) <= KL(stock)`): savings `>= (b_stock - b496)/b_stock`;
   - bracketed (`KL(b560) < KL(stock) < KL(b496)`): exact log-linear parity rate
     `b_match = b496 + (b560 - b496) * ln(K496/Kstock) / ln(K496/K560)` and savings
     `(b_stock - b_match)/b_stock`;
   - above (`KL(b560) >= KL(stock)`): savings `<= (b_stock - b560)/b_stock`.
5. Transfer at 27B (independent of 4B `PRED-M1-01`): 27B `hEBG128:b560s16` beats 27B
   `hZBG128:b560s16` by `>= 2.0` combined SE on WikiText KL **and** lands in a strictly
   better savings regime than `hZBG128` (or equal-regime with a direct `b560` KL win);
   otherwise record non-transfer at 27B (this does not falsify 4B `PRED-M1-01`).
6. Headline persistence check: 27B `hZBG128:b560s16` vs this stratum's matched
   `file:Q4_K_M-imat` — report the KL delta in combined SE and the iso-KL block savings;
   compare the savings magnitude against the 4B (10.0%) and 12B (10.6% provisional /
   recomputed) figures as the "4B -> 12B -> 27B" trend.

## What would falsify

- Any `other_tensors_that_differ != []` row, or a failed zero-codeword gate: the run is
  invalid, fix the runner before interpreting (steelman before falsify).
- `PRED-M1-01` transfer at 27B is falsified if `hEBG128:b560s16` fails rule 5.
- The "advantage persists at 27B" claim is falsified if `hZBG128:b560s16` lands in the
  `above` regime vs matched stock on WikiText (savings `<= (b_stock - b560)/b_stock`).
