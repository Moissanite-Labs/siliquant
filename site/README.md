# Results report

`results.html` is the source for the archived GitHub Pages report and the PDF. Edit the report there, keeping the evidence status and commit-pinned links with each result. The earlier codebook study and its PDF remain in `docs/`.

Build both editions with Python 3 and a recent Chrome or Chromium:

```sh
python3 site/build_results.py
# If the browser has a different executable name:
python3 site/build_results.py --chrome chromium
```

Commit `docs/archive/results-2026-11-24.html` and `docs/siliquant-results.pdf` together. The builder leaves `docs/index.html` unchanged. Open the archived HTML or serve `docs/` locally with `python3 -m http.server --directory docs`. The PDF uses the same report body with a print layout; browser versions and fonts can change the rendering. The existing GitHub Pages source is `main:/docs`.

# Research hub

`docs/hub.html` and `docs/data.json` are generated by `site/build_hub.py` from `site/hub_template.html` and the records on main; the curated report above stays the Pages homepage at `docs/index.html`. Every number in the hub is parsed from a source file in this repo or fetched from the GitHub API at build time. The builder exits non-zero on any missing or unparsable record, a missing headline arm, or a missing roofline row, and `--check` verifies the committed `docs/data.json` against the sources.

```sh
python3 site/build_hub.py --fetch-prs         # needs GITHUB_TOKEN; rewrites docs/hub.html and docs/data.json
python3 site/build_hub.py --prs-json prs.json # use a saved `gh pr list --json` file instead
python3 site/build_hub.py --check --fetch-prs # verify the committed data.json against the sources
```

`.github/workflows/hub.yml` rebuilds the hub on merges to main that touch `experiments/`, the builder, or the hub files, and commits the regenerated files with `[skip ci]`.
